libassimp: minor
---

Stream converted output to the host instead of assembling it in the engine, and report what happened during a conversion. Wasm output chunks land in a resizable host buffer, returned without a final join on Node.js and moved to a fixed-length buffer in browsers, whose Web APIs reject resizable views; native output bytes are handed to JavaScript without a copy. With JSPI or native, the engine frees the entry file once it is imported. Every result now carries `warnings`, per-phase `timings` and `peakMemoryBytes`, and `onProgress` reports throttled `import`, `postProcess` and `export` progress on both backends. Allocation failure reports `LIMIT_EXCEEDED` and leaves the instance usable, a Wasm runtime that traps is replaced on the next conversion, and `recycleAboveBytes` lets any instance drop a large idle Wasm heap. Node.js gains `createDirectoryResolver(root)`, a sidecar resolver confined to one directory.

Breaking: outputs are named after the entry file's stem with the target's canonical extension (`chair.obj` to `step` gives `chair.step`, not `result.stp`), so USDZ members and every sidecar reference change bytes too, and output bytes are typed `Uint8Array<ArrayBuffer>` (on Node.js a Wasm output's buffer may be resizable). `dispose()` returns a Promise that settles after queued work drains. A native backend that cannot load reports `BACKEND_UNAVAILABLE` instead of `IMPORT_FAILED`, and anything the engine throws that is not already an `AssimpError` rejects as `ENGINE_FAILED` with the original value as `cause`; `LIMIT_EXCEEDED`, `ABORTED` and `INTERNAL` are also new codes. Empty or repeated input names reject with `INVALID_OPTIONS`. Unset `AssimpError` context fields are absent rather than `undefined`. The native addon no longer exports `importFormats` or `exportFormats`; use `assimpCapabilities`.
