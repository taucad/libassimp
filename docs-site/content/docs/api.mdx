Every export below comes from `libassimp`, and identically from
`libassimp/importer` and `libassimp/exporter`. The two entries differ only in
the `ExportFormat` ids they accept and the importers compiled into their
binary.

## `convert`

Convert one model, or a model and the files it references, to another format.

```typescript
import type { AssimpFile, ConvertOptions, ConvertResult } from 'libassimp';

export declare const convert: (
  files: AssimpFile | readonly AssimpFile[],
  options: ConvertOptions,
) => Promise<ConvertResult>;
```

- **Parameters**: the model as a single file, or an array whose first element
  is the entry file and whose other elements are available to be referenced;
  and the target format with any per-call settings.
- **Returns**: the files the exporter wrote, primary output first.
- **Throws**: `AssimpError` when the format is unavailable to this entry or a
  conversion phase fails.

Calls share one lazily created instance per process, so the first call pays for
loading the binary and later calls do not. Reach for `createAssimp` when you
want that lifetime in your own hands.

<ConvertDemo>

```typescript
import { convert } from 'libassimp';

import { readFile } from 'node:fs/promises';

const bytes = new Uint8Array(await readFile('cube.obj'));
const { files } = await convert({ name: 'cube.obj', bytes }, { to: 'glb' });

console.log(files[0].name);
```

</ConvertDemo>

## `createAssimp`

Create an instance whose lifetime, binary location and diagnostics you control.

```typescript
import type { Assimp, CreateAssimpOptions } from 'libassimp';

export declare const createAssimp: (options?: CreateAssimpOptions) => Promise<Assimp>;
```

- **Parameters**: where to load the binary from, and where to send the
  engine's diagnostic lines.
- **Returns**: a loaded instance, with the format tables its build carries.
- **Throws**: whatever fetching or instantiating the binary threw.

```typescript
import { createAssimp } from 'libassimp';

using assimp = await createAssimp({
  onLog: ({ level, message }) => {
    console[level === 'error' ? 'error' : 'log'](message);
  },
});

const bytes = new Uint8Array();
const { files } = await assimp.convert({ name: 'model.stl', bytes }, { to: '3mf' });

console.log(files[0].name);
```

`using` disposes the instance at the end of the scope; `assimp.dispose()` does
the same by hand. Conversions on a disposed instance reject, so create another
rather than retrying on it. Instances are independent: two of them hold two
compiled modules and two heaps.

## Failures

A failed conversion rejects with an `AssimpError`: a normal `Error` with a
stable `code`, carrying the engine's own diagnostic text as its message.

### `AssimpFailureCode`

<auto-type-table path="./props.ts" name="AssimpFailureCode" />

```typescript
import { AssimpError, convert } from 'libassimp';

const bytes = new Uint8Array();

try {
  await convert({ name: 'model.obj', bytes }, { to: 'glb' });
} catch (error) {
  if (error instanceof AssimpError && error.code === 'IMPORT_FAILED') {
    console.error(error.message);
  }
}
```

[Handle failures](/docs/guides/handle-failures) turns each code into a
decision.

## Versioning

Versions follow Semantic Versioning. Before 1.0 a minor release may carry a
breaking API change, and each one is recorded in
[BREAKING_CHANGES.md](https://github.com/taucad/libassimp/blob/main/BREAKING_CHANGES.md).
