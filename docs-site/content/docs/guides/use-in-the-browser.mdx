---
title: Use in the browser
description: Load a build in a page or a worker, control where its binary comes from, and hand the result back to the user.
---

The browser story is the Node.js story with two extra questions: where the
binary comes from, and which thread the conversion runs on.

### 1. Convert bytes a user picked

<ConvertDemo>

```typescript
import { convert } from 'libassimp/importer';

const toGlb = async (file: File): Promise<Uint8Array> => {
  const bytes = new Uint8Array(await file.arrayBuffer());
  const { files } = await convert({ name: file.name, bytes }, { to: 'glb' });
  return files[0].bytes;
};
```

</ConvertDemo>

The file's own name carries the extension the importer needs, so pass it
through rather than renaming to something generic.

### 2. Let the bundler place the binary, or place it yourself

Vite and webpack 5 emit the binary as an asset from the `new URL` reference
inside the entry, which needs no configuration. When you serve it from a CDN
or a hashed directory, name the location and keep the instance:

```typescript
import { createAssimp } from 'libassimp/importer';

const assimp = await createAssimp({
  wasmUrl: new URL('/assets/libassimp-importer.wasm', window.location.href),
});

console.log(assimp.formats.export.length);
```

The binary is several megabytes, so serve it with a long-lived cache header
and a content hash in the name. Compressed transfer matters more than the raw
figure: the exporter build is under 1.3 MB over brotli. These docs self-host
the full build pinned to their commit; an application should bundle the
narrowest binary it ships.

### 3. Move the work off the main thread

A conversion holds its thread until it finishes, which on a large model is
long enough for a page to drop frames. Import the entry inside a worker
module and post the bytes in:

```typescript
const worker = new Worker(new URL('./convert-worker.js', import.meta.url), { type: 'module' });

worker.postMessage({ name: 'model.fbx', bytes: new Uint8Array() });
```

The worker imports `libassimp/importer`, calls `convert`, and posts the result
back. Nothing else is needed: the binaries carry no threads, so no
cross-origin isolation headers are involved.

### 4. Hand the result to the user

The result is plain bytes, so a download is a blob and a link.

```typescript
const download = (name: string, bytes: Uint8Array<ArrayBuffer>): void => {
  const url = URL.createObjectURL(new Blob([bytes], { type: 'model/gltf-binary' }));
  const anchor = Object.assign(document.createElement('a'), { download: name, href: url });
  anchor.click();
  URL.revokeObjectURL(url);
};
```

## Variations

**Loading eagerly.** The first `convert` fetches and instantiates the binary.
Call `createAssimp()` while the user is still choosing a file to move that
cost off the conversion.

**Hosts without WebAssembly.** There is nothing to fall back to in the
package; feature-detect and route the work to a server.
