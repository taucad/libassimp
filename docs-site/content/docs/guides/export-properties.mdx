---
title: Set export properties
description: Reach assimp's own exporter settings, such as 3MF units, without leaving the typed API.
---

Some exporters read settings that have no place in a cross-format API: 3MF
units, the application name written into a file's metadata. `properties` passes
those through verbatim.

### 1. Name the property the exporter documents

```typescript
import { convert } from 'libassimp';

const bytes = new Uint8Array();

const { files } = await convert(
  { name: 'part.stl', bytes },
  {
    to: '3mf',
    properties: {
      '3MF_EXPORT_UNIT': 'millimeter',
      '3MF_EXPORT_APPLICATION': 'my-slicer',
    },
  },
);

console.log(files[0].name);
```

Values are booleans, numbers or strings, and each goes to the exporter with
its own type. Keys the exporter does not recognise are ignored, so a property
meant for one target is harmless when another runs.

### 2. Expect silence, not validation

The engine has no schema for these names. A misspelled key changes nothing,
and a value outside what an exporter accepts — `3MF_EXPORT_DECIMAL_PRECISION`
below its floor, say — fails the call with `EXPORT_FAILED` and the exporter's
own message. Assert on the output rather than trusting a setting took:

```typescript
import { convert } from 'libassimp';

const bytes = new Uint8Array();
const asText = async (unit: string): Promise<string> => {
  const { files } = await convert(
    { name: 'part.stl', bytes },
    { to: 'assjson', properties: { '3MF_EXPORT_UNIT': unit } },
  );
  return new TextDecoder().decode(files[0].bytes);
};

console.log((await asText('meter')).length);
```

### 3. Know the one property already set

Assimp's JSON dump is written without whitespace: `JSON_SKIP_WHITESPACES` is
on by default, because a scene dump is machine input. Pass it as `false` to get
an indented file.

```typescript
import { convert } from 'libassimp';

const bytes = new Uint8Array();

const { files } = await convert(
  { name: 'part.stl', bytes },
  { to: 'assjson', properties: { JSON_SKIP_WHITESPACES: false } },
);

console.log(files[0].name, files[0].bytes.byteLength);
```

## Variations

**Per-call, not per-instance.** Properties belong to one conversion; two calls
on one instance never share them.

**Post-processing steps.** Import-side behaviour is fixed in 0.1.0 and is not
reachable through `properties`; see
[How it works](../how-it-works#post-processing).
