title: Choose an entry
description: Trade binary size against the formats you can name, and pick the import specifier that covers your conversion.

The three entries are the same API over three binaries. Picking one is a size
decision, and the only one the package asks you to make.

<SizeStrip />

### 1. Start from the direction you convert

| You need                               | Import               |
| -------------------------------------- | -------------------- |
| Anything in, glTF or GLB out           | `libassimp/importer` |
| glTF, GLB, USD or VRM in, anything out | `libassimp/exporter` |
| Anything in, anything out              | `libassimp`          |

Most pipelines are one of the first two. An upload endpoint normalising
customer files into GLB reads everything and writes one format; a viewer
exporting its own glTF scene to 3MF or STEP reads one format and writes
everything.

<ConvertDemo>

```typescript
import { convert } from 'libassimp/importer';

import { readFile } from 'node:fs/promises';

const bytes = new Uint8Array(await readFile('cube.obj'));
const { files } = await convert({ name: 'cube.obj', bytes }, { to: 'glb' });

console.log(files[0].name);
```

</ConvertDemo>

### 2. Chain two entries rather than reaching for the third

A conversion whose ends are both exotic — FBX to STEP, say — can go through
glTF, and two narrow binaries can still be smaller than one wide one. The
intermediate never touches disk.

```typescript
import { convert as toGltf } from 'libassimp/importer';
import { convert as fromGltf } from 'libassimp/exporter';

const bytes = new Uint8Array();
const { files: gltf } = await toGltf({ name: 'model.fbx', bytes }, { to: 'glb' });
const { files } = await fromGltf({ name: 'model.glb', bytes: gltf[0].bytes }, { to: 'step' });

console.log(files[0].name);
```

Each hop is a full import and export, so a scene loses anything glTF cannot
carry. Reach for the root entry when that matters more than the megabytes.

### 3. Confirm the build at runtime

Every instance reports the tables it was compiled with.

```typescript
import { createAssimp } from 'libassimp/exporter';

using assimp = await createAssimp();

console.log(assimp.formats.export.map((format) => format.id).join(' '));
```

A `to` id absent from that list fails with `UNSUPPORTED_FORMAT` rather than
silently writing something else. The full tables are on
[How it works](../how-it-works).

## Variations

**Loading both entries in one process.** Each holds its own module and heap, so
the cost is the sum of the binaries. Loading is lazy: an entry you import but
never call costs nothing at runtime.
